# shot 原型计算与文件格式

## 计算约定

`web/model.js` 可在浏览器和 Node.js 使用。时间、事件、规则和玩家画像分别传入 `analyze`，输入不会被修改。

事件原始时间可用小数秒，区间采用 `[start, start + duration)`，持续 0 秒的事件只触发瞬时和延迟影响。模拟按 1 秒及事件起止、延迟边界划分计算区间。分析时元仅用于曲线采样；粗采样可能平滑瞬时峰值，诊断和最低值仍在内部步长检查。

整体参与意愿按内部区间右端的状态、区间长度加权平均。最后一个时间戳处的瞬时事件影响终态和最低值，不占用时间权重。空项目仍输出初始状态。延迟影响可延伸时间轴；上限包含延迟后的时间。

状态包括期待、压力、疲劳、能力感、挫败、无聊（0–10）和按机制记录的知识（0–1）。画像能力作为初始能力感。教学依赖反馈清晰度、学习速度和时长增加对应机制知识，挑战开始时检查前置知识；挑战过程中知识不足或难度失配累积挫败。

知识不会在挑战中自动增加；若挑战包含教学，可以填写「教学机制」。同一时间发生的事件按输入数组顺序处理，零时长教学不会建立知识。重复计数为整个流程中同机制挑战的累计次数，休整不会清空计数。它只是调查线索，不能证明玩家已经厌倦。

## 规则包

从网页导出默认规则，编辑完整 JSON 后导入。必须保留 `version: 1` 及必需字段；未通过验证不会替换已有项目。没有 `eval`、脚本或公式执行功能。

| 字段 | 含义 |
| --- | --- |
| `name` | 规则名称 |
| `decay` | 各状态每秒指数衰减率，0–1 |
| `weights` | `base` 基线以及六个状态对参与意愿的权重，−10–10 |
| `thresholds` | 知识、重复次数、疲劳、挑战失配、无聊、奖励间隔的诊断阈值 |
| `mappings` | 八种事件类型到状态影响函数的数组，必须包含每种事件类型 |
| `dynamics` | 学习、知识缺失惩罚、挑战失配惩罚、重复疲劳、低活动宽限、无聊及恢复的参数 |

影响函数格式示例：

```json
{ "state": "fatigue", "mode": "accumulate", "coefficient": 0.003, "attribute": "intensity" }
```

| `mode` | 行为 |
| --- | --- |
| `instant` | 事件开始时一次增加 `coefficient × attribute` |
| `sustain` | 事件生效时向该目标值逐步靠近；并发同状态目标相加后限幅 |
| `accumulate` | 按生效区间长度累积 |
| `delayed` | 开始后 `delay` 秒触发一次，可超过事件结束 |
| `recover` | 按非负系数指数恢复 |

省略 `attribute` 时倍率为 1。属性限定为强度、难度、新颖度、反馈、价值、失败成本。系数和状态值有数值约束，不支持自定义状态名称。

休整或没有活动的时间超过 `idleGrace` 后累积无聊；其他活动降低无聊。失败的反馈清晰度降低其瞬时挫败影响。

参与意愿按规则权重计算，疲劳、挫败、期待分别受到画像敏感度和偏好修正。唤醒与效价在 v1 使用固定公式：

- 唤醒 = 压力 × 0.75 + 期待 × 0.25。
- 效价 = 5 + 能力感 × 0.25 + 期待 × 0.2 − 挫败 × 0.5 − 无聊 × 0.3。

所有输出限幅到 0–10。以上系数是工作假设，没有心理测量效度保证。

## 玩家画像

导出画像后修改 `name`、`skill`（0–10）以及 `fatigueSensitivity`、`frustrationSensitivity`、`noveltyPreference`、`learningRate`（0.1–3），再导入。切换画像不会修改事件输入。

## 项目

项目 JSON 包含 `version: 1`、`events`、`rules`、`profile`、`unit`。事件由 `makeEvent` 定义，包含 ID、名称、类型、开始时间、持续时间、六种属性、教学机制和所需机制。事件属性为 0–10；ID 不得重复；最多 300 个事件，最长 7200 秒，时元为 1–300 秒。导入文件不得超过 2 MB。

每次分析是一个独立会话，分别保存项目数据。左侧可以新建和切换，顶部名称可以修改。旧版单项目本地数据自动迁移为第一个会话。导入导出针对当前方案，不会替换其他方案或会话。

页面右侧悬浮会话配置区提供规则、用户类型、分析精度、规则导入、玩家类型导入和开始分析。配置区随页面滚动保持可用，配置操作与开始分析在更新布局后恢复当前滚动位置；若页面变短而原位置超出页面范围，只能保留到新的页面末端。精度按采样间隔秒数设置；修改内容后保留上次结果并显示待更新提示，只有开始分析才更新结果。刷新后保留各方案配置和最后一次分析快照。时间轴总长度位于点阵下方，方案比对位于曲线区域。

规则和玩家类型配置库在各会话间共享，当前选择仍属于各自会话。独立编辑器通过 JSON 编辑配置，验证后保存为新条目或导出；编辑器不会覆盖已存在会话的配置。导入和保存的新条目可以在任意会话的下拉菜单中选择。

时间轴按 `unit` 划分点阵格子。点击格子只建立草稿，保存后才加入项目。区间事件按持续时间显示为横向块，瞬时事件显示为单个标记；重叠事件自动分层。事件可选的 `lane` 是显示层，`timelineLength` 是会话中的显示范围，两者都不进入模型计算。改变采样间隔不改变事件原始时间；拖动则将新开始时间吸附到时元格子，持续时间保持不变。

预设库保存在浏览器的会话工作区数据中，与规则库一样跨会话共享。预设保存的是事件模板，不携带原始位置和显示层。长按拖入时生成新 ID 和独立事件属性副本，后续模板修改不会同步到已有事件。项目导出包含当前时间轴事件与显示参数，不包含整个全局预设库。

每个会话包含最多 30 个独立方案，可切换、命名、新建空白方案或基于当前方案复制。空白方案沿用当前规则、玩家类型和精度，但不包含事件；复制方案包含当前完整配置与事件，生成曲线需开始分析。项目 JSON 导入导出针对当前方案。

曲线区域通过勾选方案显示各自最后一次分析结果，颜色区分指标，线型区分方案（五种线型循环使用）。横轴覆盖已勾选且已分析方案的最大时长，不对时间进行归一化。勾选未分析方案不会自动运行；修改后保留上次曲线并标记待重新分析。比较时应检查时长、规则与玩家类型变化是否符合实验目的。

浏览器保存结构升级到 version 2：每个会话包含 plans、activePlanId 和 comparisonIds。原 version 1 会话自动迁移为「方案 1」，保留原项目数据。每个方案持久化完整项目与最后分析时的项目快照，刷新时由该快照重新计算结果；快照与当前配置不同则提示待更新。

诊断包括机制知识不足、重复体验、挑战失配、疲劳积累、长时间低活动、奖励投入脱节。每条记录有时间、相关事件（如有）、规则 ID、阈值证据与修改假设。按规则和事件去重，因此不表达异常持续区间。它们不进行真实因果推断。

「开始分析」默认更新当前会话的所有方案，不受曲线勾选范围影响；未修改的分析结果复用。勾选「仅分析当前方案」后，只更新激活方案，其他方案保留原结果及待更新状态。该选项每次打开页面默认不勾选。
