# shot 需求记录

来源：[游戏历程评价模型对话](https://chatgpt.com/share/6ac883de-9b14-83ec-b153-2f3bd925ac20)。

shot 指整个关卡历程分析工具；首版交付为可交互网页原型。

## 目标

量化分析一段游戏历程，定位体验问题，形成可以通过关卡修改和试玩验证的设计假设。重点是分析和诊断，并支持设计阶段推演。

## 核心原则

- 时间轴、事件、评分规则、玩家画像分别配置。
- 事件记录设计属性，不直接保存“兴奋度 +3”等预测评分。
- 原始事件时间戳保持不变，支持区间、瞬时事件和事件重叠。
- 模型预测、分析者观察和玩家实测明确区分。
- 低唤醒和高压力不自动等同于设计缺陷，诊断需要结合设计意图。

## 对话确定的能力

1. 可定义分析时元，例如 1 秒、5 秒、30 秒及自定义值。
2. 时间轴上添加、编辑游戏事件，包括剧情、挑战、奖励、目标、探索和休整。
3. 导入评分规则包，包含事件映射、时间影响函数、状态更新参数和诊断阈值。
4. 独立配置玩家画像，支持同一事件序列在不同玩家类型下分析。
5. 状态保留历史：期待、疲劳、压力、能力感、挫败，以及按机制记录的知识。
6. 输出参与意愿、情绪唤醒和情绪效价的时间曲线。
7. 诊断记录异常时间、事件、触发规则、相关状态、可能原因和修改假设。
8. 对修改前后流程进行反事实对比；结果用于提出假设，不能证明真实玩家体验改善。

## 首版候选验收标准

- 同一流程在不同分析时元下保持相同的整体计算结果，改变输出采样密度；内部步长与分析时元明确区分。
- 瞬时事件只触发一次，区间事件按实际覆盖时间产生影响，事件顺序能够影响机制知识和后续体验。
- 规则导入有结构和数值校验，不执行导入文件中的任意代码。
- 不同玩家画像可以影响同一流程的结果，事件记录不被画像选择修改。
- 使用 Portal 2 的标准、重复、错序三种假想流程检验知识缺失、重复疲劳和休整作用。
- 休整降低疲劳，同时考虑过长休整的无聊与期待衰减；不预设“越长越好”。
- 诊断能追溯具体输入和规则，不只显示总分。
- 示例数据标注为假想设计输入，输出标注为模型预测。
