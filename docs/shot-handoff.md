## 产品目标及已确认交互

shot 是关卡历程分析工具的可交互网页原型。用户录入事件流程，选择规则和玩家类型，分析节奏，再通过多个方案比对调整效果。模型参数尚未经过真实玩家数据校准。

产品层次是：**项目分组 → 会话 → 方案 → 事件**。项目只负责组织会话，不给成员会话施加共享规则。规则库、玩家类型库和事件预设库在整个浏览器工作区共享；选择后的配置和放入时间轴的事件是独立副本。

### 左侧会话与项目管理（最新工作区）

- 风格参考 ChatGPT：每行会话有「⋯」菜单，支持重命名、置顶、移动到项目、归档、删除。
- 置顶会话集中显示在顶部；项目成员关系仍保留，取消置顶后回到原项目。
- 项目支持新建、重命名、折叠、组内新建会话、删除分组。
- 删除项目仅移除分组，会话保留；删除会话删除其全部方案，必须通过页面确认对话框。
- 归档列表支持打开、恢复和删除会话；归档不会清除方案或分析快照。
- 删除或归档当前会话后切换到其他未归档会话；没有可用会话时自动新建空白会话。
- 菜单使用原生 `<dialog>`；删除确认使用 `window.confirm`。手机端支持直接打开菜单，键盘可以聚焦后按 Enter。
- 没有账号、云同步、搜索、项目共享或多人协作功能。

### 右侧悬浮配置及方案

- 「方案」分区：切换、重命名、新建空白方案、基于当前方案新建。
- 空白方案沿用当前规则、玩家类型和精度，但清空事件及显式时间轴范围。
- 复制方案复制当前配置和事件，不复制分析结果，需开始分析。
- 「分析配置」分区：规则、玩家类型、采样间隔、导入规则、导入玩家类型、分析范围和开始分析。
- 「仅分析当前方案」是复选框，**默认不勾选，每次打开页面重置为未勾选**。
- 默认分析当前会话全部方案；勾选后只分析激活方案。范围不跨会话，也不由曲线显示勾选决定。
- 相同项目快照的结果复用；全部目标计算成功后再一起更新，避免曲线只更新一部分。
- 桌面固定右侧；手机默认收起，通过右下角按钮打开。配置操作、导入和分析保持页面滚动位置；页面缩短时位置只能保留到新页面末端。

### 时间轴、事件和预设

- 横向时间轴，顶部以时元（采样间隔）显示刻度，下方点阵是放置事件的格子。
- 点击空白格只创建草稿；下方事件编辑器保存后才添加。点击已有事件在同一编辑器修改。
- 已有事件可拖动，按时元吸附，保留持续时间；纵向层用于排列重叠事件。
- 右键菜单：删除、复制到下一层、保存为预设。
- 时间轴右侧是预设事件库。长按约 350 ms 拖入时间轴生成独立副本；点击卡片在事件编辑器管理预设。
- 移出有效区域、Escape、pointercancel 或窗口失焦取消拖动；支持边缘横向滚动。
- 时间轴总长度在点阵下方。原示例选择和独立新增按钮已经移除。

### 曲线、比对和诊断

- 已移除原来的基线比较，用方案勾选框显示各方案最后一次分析曲线。
- 颜色表示指标：参与意愿、唤醒、效价、疲劳；线型表示方案，五种线型循环使用。
- 横轴使用实际秒数，范围覆盖已勾选且已分析方案的最大时长，不对时长做归一化。
- 未分析方案不会因勾选而自动分析；修改后显示旧结果及「待重新分析」提示。
- 指标摘要和诊断属于当前激活方案；勾选多个方案不会合并诊断。
- **没有调用语言模型。** 诊断由状态计算及阈值条件触发，证据包含计算数值；修改假设是 `model.js` 中预先写好的文案。
- 规则 JSON 可以改变映射、权重、衰减、动力学参数和阈值；不能通过 JSON 任意新增诊断判断程序或生成建议文案。

## 运行与验证

Node.js 20+，原生 HTML/CSS/ES modules，无前端框架、构建器、数据库或运行时第三方依赖。

```bash
cd /workspace/LDtools
npm start
```

默认地址 `http://127.0.0.1:3000`；需要端口转发时用 `HOST=0.0.0.0 PORT=3000 npm start`。服务只提供 `web/` 静态文件，没有保存数据或模型 API。不要把开发服务器启动成功等同于网站已经公网部署。

```bash
npm --cache /workspace/.cache/npm ci
npm test
SHOT_BROWSER_PATH=/usr/bin/chromium npm run test:browser
```

没有系统 Chromium 时，可执行 `npx playwright install chromium`，然后 `npm run test:browser`。浏览器测试自行启动临时服务器，无需提前运行 `npm start`。

## 数据与迁移

存储在当前浏览器 localStorage：

- 当前工作区键：`ldtools-shot-sessions-v1`。键名仍含 v1，内部数据 `version` 已为 2，不要因此改键名导致旧数据丢失。
- 旧单项目键：`ldtools-shot-v1`。没有工作区时读取并迁移。
- 工作区字段：`version`、`activeSessionId`、`sessions`、`groups`、`ruleLibrary`、`profileLibrary`、`presets`。
- 会话字段：`id`、`title`、`groupId`、`pinned`、`archived`、`plans`、`activePlanId`、`comparisonIds`、`project`。`project` 是当前激活方案的镜像，真正方案数据位于 `plans`。
- 分组字段：`id`、`name`、`collapsed`。
- 方案字段：`id`、`name`、`project`、`analyzedProject`。后者是上次分析输入的 JSON 字符串，不是结果数组。
- `sessionRuntime` 名称保留自早期实现，现在实际上按 **方案 ID** 存储运行时结果和选中事件。
- 刷新时用保存的 `analyzedProject` 重新计算旧结果，用 JSON 字符串比较当前项目判断待更新状态。
- 支持工作区 version 1/2；旧会话自动成为「方案 1」。缺少项目分组和归档字段的旧数据兼容读取。

项目 JSON 导入导出仍是 `validateProject()` 所定义的单方案结构，**不包含整个会话、多方案、项目分组或全局配置库**。当前尚无整个工作区导出/恢复功能。

localStorage 按浏览器和来源地址隔离；换浏览器、端口或打开另一份本地 HTML 可能看不到原数据。容量或权限不足会显示保存失败提示。若要跨设备交接真实分析，请分别导出方案、规则和玩家配置，或后续增加工作区备份功能。

输入限制：每方案最多 300 个事件；每会话最多 30 个方案；最多 100 个项目；预设库最多 300 条；流程最长 7200 秒（含延迟影响）；采样间隔 1–300 秒；导入 JSON 最大 2 MB。

计算与显示采样分离：模型在事件/延迟边界与内部时间步上计算，采样间隔只控制输出曲线采样，也被 UI 用作时间轴网格吸附单位。改变采样不应改变模型摘要和诊断；粗采样可能平滑掉图上的瞬时变化。
