# LDtools

关卡设计工具集。首个工具 **shot** 是一个可交互的关卡历程分析网页原型。

## 启动 shot

需要 Node.js 20 或更新版本。应用没有运行时依赖，不需要数据库、账号或 API 密钥。

```bash
git clone https://github.com/alexyankq/LDtools.git
cd LDtools
npm start
```

在运行机器的浏览器打开 `http://127.0.0.1:3000`。默认只监听本机；需要在支持端口转发的开发环境访问时，可以用 `HOST=0.0.0.0 PORT=3000 npm start`。

## 使用

左侧「我的分析」管理独立的分析会话。点击「新建分析」开始空白会话，点击已有会话继续编辑；顶部名称可直接修改。各会话分别保存事件、规则、画像和时元，切换时不会互相覆盖。页面刷新后恢复会话列表和上次打开的会话；旧版单项目数据会迁移为第一个会话。

1. 在当前会话配置栏选择规则、用户类型、分析精度（每隔多少秒采样一次）。可在时间轴区域载入 Portal 2 的标准、重复或错序示例。
2. 点击时间轴、事件表或诊断中的「定位事件」，在右侧编辑事件并保存。点击配置栏的「开始分析」更新曲线和诊断；修改配置或事件不会自动替换上次结果，页面会提示结果待更新。
3. 点击「设为对比基线」，再调整事件、玩家或规则，比较曲线和平均参与意愿的预测差异。
4. 在配置栏导入规则或玩家类型 JSON，导入后自动选中。左侧「规则编辑器」「玩家类型编辑器」独立负责编辑、保存为新条目及导出 JSON。配置库可跨会话复用，保存新条目不会覆盖其他会话；会话中选择后再开始分析。导入项目可以恢复整套配置。
5. 会话和配置库自动保存在此浏览器的 localStorage；项目导入导出操作针对当前会话，请分别导出 JSON 以便跨设备使用和备份。分析结果和基线按会话保留在当前页面，刷新后需重新分析并设置基线。编辑事件后需要点击保存；切换示例时，自定义流程会自动导出备份。

## 时间轴与预设

配置栏下方是横向的「时间轴－事件编辑器」。顶部刻度根据分析时元生成，下方点阵表示可填充事件的位置。横向滚动查看后续时间，纵向分层用于排列重叠事件。

- 点击空格子，在下方填写事件内容，点击「保存新增事件」才加入当前会话。
- 点击已有事件，在同一个编辑器修改并保存；也可直接拖动事件，按时元吸附到新位置，持续时间保持不变。
- 右键事件，可删除、复制或保存为预设。复制保留原始时间与属性，并放到下一层。
- 右侧预设库中的卡片长按约半秒后可拖入格子，松开即添加独立事件。拖到时间轴外或按 Escape 则取消。
- 点击预设卡片，在下方管理其内容；支持新建、修改、另存和删除。预设在会话间共享，修改或删除预设不会改变已经添加的事件。

时间轴范围可手动调整，也会自动扩展以容纳已有事件，最长两小时。拖动若会使事件超出两小时上限，则不会保存该移动。

示例事件是假想设计输入。模型结果和诊断均为实验性预测，参数尚未通过真实玩家数据校准，不能视为实测体验或设计缺陷的证明。

## 验证

```bash
npm test
```

模型测试覆盖时元一致性、教学顺序、重复疲劳、瞬时与小数时间、重叠事件、延迟影响、休整、玩家差异和输入校验。

浏览器测试会自行启动临时服务器，验证交互、导入导出、本地保存和移动端布局：

```bash
npm ci
npx playwright install chromium
npm run test:browser
```

如已安装系统 Chromium，可跳过浏览器下载，用 `SHOT_BROWSER_PATH=/usr/bin/chromium npm run test:browser`。受限环境中可以通过 `npm --cache /workspace/.cache/npm ci` 将 npm 缓存放在可写目录。

完整需求见 [shot 需求](docs/shot-requirements.md)，配置与计算约定见 [模型说明](docs/shot-model.md)。
